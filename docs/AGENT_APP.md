# 轻微 MCP 0.2.0

这一版本统一使用 Miuix。会话、模型及附件交互参考 [DSH Go](https://github.com/ccch1mneyyy/dsh-Go)。MCP HTTP 宿主、Root IPC 桥接和 JNI 库均在主 APK 中，手机继续使用原有 KO。

## 安装与升级

Actions 的 `qingwei-apks` Artifact 提供：

- `qingwei.apk`：固定签名的正式安装包，包名 `com.kernelai.app`。
- `qingwei-debug.apk`：调试/自动化验收包，包名 `com.kernelai.app.debug`。
- `qingwei-android-test.apk`：仅供自动测试，不需要安装到日常使用的手机。

日常只安装 `qingwei.apk`，首次启动请授予 Root 权限以连接驱动。0.2.0 起仓库 Actions 使用加密 Secrets 中的固定签名；后续同包名、同签名更新可以保留私有数据。此前 Actions 的临时 Debug 签名无法恢复，因此旧 Debug 包不能用新签名直接覆盖；卸载旧包前保留其 AI 地址、模型和密钥。正式包与旧 Debug 包的包名不同，可先完成正式包配置再移除旧版。

本次未修改驱动源码、JNI 和 ioctl ABI，不需要重新编译或重载 KO。默认端口被其他应用占用时会选择可用端口，接入地址以设置页面实际显示为准。主 App 的“驱动连接”和“MCP 服务”是独立状态，MCP 可启动不代表驱动已打开。

## 对话与模型

顶部会话按钮打开对话列表，可搜索、改名、删除和切换。消息、工具参数与结果、草稿、附件、会话模型选择和待处理插话保存在 App 私有目录；写入采用临时文件、fsync 和同目录替换，流式期间定期保存。恢复时将未完成操作标记为取消/结果未确认，保留已经收到的正文。对话内容不是云端同步，卸载会移除本机数据。

在“设置 → 模型与供应商”添加 OpenAI Chat Completions 兼容供应商，填写名称、带接口前缀的 Base URL 和密钥。例如接口为 `/v1/chat/completions`，Base URL 填到 `/v1`。密钥在 Android Keystore 保护下加密保存，已有单供应商配置会迁移。

“保存并获取”或“获取模型”请求 `GET <Base URL>/models`，选择要添加的模型；也可以手动输入模型 ID。编辑模型可设置显示名称、上下文窗口、最大输出、Temperature、图像输入、重试次数以及流式 usage 支持。获取列表不会猜测模型的上下文长度和图像能力。聊天窗口中可切换供应商下的模型，已有会话保留各自选择。

上下文显示区分本地估算和服务端上次实测。服务端未返回 usage 时仍显示估算；估算不是精确分词计数，图像 token 也因供应商而异。估算上下文与输出预算超过窗口时停止请求并提示调整，不悄悄删除历史。

默认最多自动重试 **5 次**（初次请求之外），只在尚无正文/工具参数输出且遇到暂时网络错误、429 或 5xx 时重试。采用有界退避，可停止等待。鉴权、参数和格式错误直接报告；已收到部分输出后不自动重新生成，设备工具执行不因模型请求重试而重放。

## 附件、工具与产物

输入框“＋”支持图片和 UTF-8 文本文件（例如日志、JSON、CSV、Markdown、代码）；每条最多 4 个附件。文本单个上限 512 KiB，图片会缩小到不超过 2048 像素并转为 JPEG，处理后单个不超过 4 MiB。图片需要所选模型启用图像能力。PDF、Office 等二进制输入目前会明确提示转换，不能把空内容当成已经分析。附件支持本机预览及发送前移除。

工具卡片优先显示本次操作目的。模型可填写 `_purpose`；未填写时根据工具和参数生成说明。总览和单项支持折叠，详情保留真实工具名、调用 ID、参数、结果、错误和耗时；运行中的文字有动态提示。正文新增部分渐显，原有文字不反复闪烁。上滑阅读会暂停自动跟随；“回到最新”恢复跟随，末尾留出悬浮输入框所需空间。

AI 可调用 `ask_user` 等待补充信息，在问题卡片选择或输入回答后继续。生成时输入消息可插话，内容在下一步模型请求前加入；也可“中断并发送”。插话最多等待 8 条，不插入尚未完成的工具调用与其结果之间。

HTML/SVG 和其他带语言标记的长代码可显示产物卡片、查看源码并导出分享。HTML/SVG 本机预览默认关闭脚本，关闭网络和文件访问；可显式启用交互脚本。Markdown 图片、安装包、压缩包、文档、媒体、KO 等链接以大卡片呈现，不自动下载远程内容；图像可按需加载并缓存，安装包等可下载后交给系统打开。图像下载上限 16 MiB，其他文件上限 256 MiB。卡片不能证明模型提供的链接真实存在，下载失败会报告。

## 真实设备查询与分析

进程、断点、内存和指令字节界面已接入同一个本机 MCP 调用链，驱动不可用时显示错误，不生成演示结果。断点列表为驱动全局硬件断点；不伪装软件断点列表或原位启停能力。指令页面读取真实字节，目前未内置反汇编器。

微信问题修复：`process_list` 有 filter 时跨原始页搜索，max_count 限制匹配结果数量；返回原始游标、是否还有数据、搜索是否完整及扫描上限。给定 1050 个进程、目标在第 900/1040 项的回归能查到两个微信 PID。`process_resolve {"pkg_name":"com.tencent.mm"}` 使用驱动全量包名查询。空页或驱动错误不代表应用未运行。

MCP 共 22 项设备/计算工具，新增 `process_resolve`、`address_calculate`、`module_address`、`memory_read_typed`、`memory_read_string`、`memory_read_struct`、`pointer_chain`、`memory_inspect`。App AI 额外拥有本机交互工具 `ask_user`。

内存单次读取最多 4096 字节，指针链最多 32 步，结构最多 64 字段。地址以无损字符串传输，检测 64 位加减溢出；支持 32/64 位指针、大小端、显式顶字节标签处理。部分读取、空指针和环会携带已完成轨迹返回错误，不补零或伪造字段。结构布局由调用者提供；候选指针不证明地址有效，也不能自动确认 Java/ART/C++ 类型。进程未暂停，多次读取不是原子快照。

## 外部 MCP 客户端

“设置 → 允许外部客户端接入”默认关闭。开启后主 App 启动前台宿主服务，在设备 IPv4 网络接口监听；无需其他宿主 APK。复制页面中的地址和 Authorization 令牌，客户端选择 Streamable HTTP，访问 `POST /mcp`：

```text
Authorization: Bearer <页面复制的令牌>
Content-Type: application/json
```

外部令牌与 App 内部令牌分开。关闭开关后回到仅本机监听，旧外部令牌立即失效；重启服务会更换令牌。切换会中断当前 HTTP 等待，不回滚已经提交给设备的操作。HTTP 不提供 TLS 加密，供可信网络使用。支持初始化返回的 `Mcp-Session-Id`，避免同一地址上不同客户端名称混淆；不带会话头的调用仍可使用，但只按连接信息记录身份。

“第三方调用记录”本地保留最近 1000 条，可筛选、搜索和展开：时间、客户端自报名称、实际连接地址、方法、工具、操作目的、参数摘要、请求 ID、耗时及状态。未授权/异常请求也有状态记录。不会记录 Authorization 头或完整内存返回，常见密钥、数据和字节模式字段会脱敏。客户端自报名称不是可信身份认证。调用记录读写出错时显示错误，并保留原文件。

## 构建签名

非 PR 的 App 工作流需要仓库 Actions Secrets：`QINGWEI_SIGNING_KEYSTORE_B64`、`QINGWEI_STORE_PASSWORD`、`QINGWEI_KEY_ALIAS`、`QINGWEI_KEY_PASSWORD`。它们分别为 PKCS12 的 Base64、存储密码、别名及密钥密码。私钥不会进入 Git、报告或 APK Artifact。PR 检查使用普通测试签名，Release 为 unsigned，不能当作正式升级包。自行本地签名时用同名密码环境变量及 `QINGWEI_KEYSTORE_PATH` 指向私有 PKCS12。

## 真机验收顺序

1. 安装正式 `qingwei.apk`，保留已加载的 KO，授予 Root 并在设置中核对驱动和内置 MCP 的实际状态。
2. 添加供应商并获取模型，按实际能力设置上下文、输出上限和图像支持。发送普通问题，再选择图片或文本日志检查附件。
3. 新建两段对话，生成较长回复：上滑时应停留阅读，点击“回到最新”后恢复跟随。切换会话、回到桌面、重新打开后核对正文、工具记录、模型和草稿。
4. 保持微信运行，让 AI 先调用 `process_resolve` 查询 `com.tencent.mm`，再以 `process_list` 搜索 `tencent`；与 Root 终端的 `pidof com.tencent.mm` 对照。查看工具详情中的扫描完整性和真实返回，不能只比较模型的口头结论。
5. 先在自己的测试进程验收模块、映射、少量内存读取及明确地址的指针链；之后再验硬件断点和写入。新版本的真机 ioctl 与长期稳定性尚未由模拟器验证。
6. 让 AI 在不明确的操作前使用 `ask_user`，核对回答后继续、生成中插话和中断发送。临时网络错误在尚无输出时最多额外重试五次，鉴权错误应直接显示。
7. 需要其他客户端时打开外部接入，使用页面实际地址及令牌调用一个只读工具，在调用记录核对时间、客户端、工具目的和状态；关闭开关后旧外部令牌应失效。
